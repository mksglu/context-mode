# Live A/B of context saving (Claude Code, keyless)

Status: run done 2026-10-19 (120 sessions). Result: bench/RESULTS.md, section Live A/B. Aggregate: bench/live/results/aggregate.json.

## Question
Does the v2 plugin cut the tokens a Claude Code session reads, on tasks with large tool output?

## Harness
- Keyless `claude -p` (ADR-0012). Same child env as `e2e/live/run.mjs`: allow-list PATH HOME USER LOGNAME SHELL TMPDIR LANG LC_ALL TERM, plus `ENABLE_CLAUDEAI_MCP_SERVERS=false`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` (D-M7-CL-3). No `ANTHROPIC_*`.
- Real binary only (Mach-O/ELF magic check).
- Flags: `-p --output-format stream-json --verbose --model claude-sonnet-5-5 --effort low --max-budget-usd 0.25 --no-session-persistence --setting-sources project`.
- Arm `on`: add `--plugin-dir release-out` (built by `node build/build.mjs --out release-out`).
- Arm `off`: add `--strict-mcp-config` (no MCP server, no plugin hooks). Built-in tools are the same in both arms.
- cwd: a fresh temp git repo per session with the local fixtures. No network. The plugin data dir for the project is deleted after each session.

## Tasks
20 tasks in `tasks.mjs`. Each one needs a large tool output: log files, test-run output, big JSON, big files, git history. Fixtures are generated by `fixtures.mjs` from a fixed seed. Each task has a script check (`check(finalText, repoDir)`) that reads the final answer. The answer is a value the model can only get by reading the data (a count, an id, a hash prefix).

## Runs
3 runs per task per arm = 120 sessions. Batches of 10 sessions, arms interleaved, order fixed by seed. After each batch the aggregate is committed and pushed.

## Measures (from stream-json `result` event usage)
- `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens` summed over the session.
- Session input = input + cache_creation + cache_read.
- `total_cost_usd` is a list-price estimate, reported as such.
- Success = script check passes and `is_error` is false.

## Saving %
Per task: `1 - median(on session input) / median(off session input)`, over the runs of that task. Reported: median, min, max over tasks. Success rate per arm = passes / sessions. Tasks where an arm has 0 passes are listed. Saving is also given over successful sessions only.

## Privacy
Raw per-session rows (prompts, paths) stay in `/private/tmp/cm-v2-impl-private/bench`. Only aggregates are committed.

No number here is a target. Every number carries date, agent version and model.
